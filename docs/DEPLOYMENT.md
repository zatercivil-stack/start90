# Развёртывание

Адрес: https://tgt.myvelum.com/
Репозиторий: https://github.com/zatercivil-stack/start90

## Production

Статические файлы dist обслуживает уже работающий Caddy. Для проекта создан отдельный каталог `/var/www/start90/releases/` и симлинк `/var/www/start90/current`. Новый домен задаётся отдельным `/etc/caddy/start90.caddy`, подключённым единственной строкой import в существующем Caddyfile. Существующие блоки не изменяются. Caddy автоматически выпускает и обновляет TLS-сертификат. Отдельный Node-процесс, Docker и БД не нужны.

Веб-корень содержит только dist. Исходники, тесты, документация, .git, ключи и runtime-файлы в него не копируются. Ответы включают nosniff, запрет iframe, no-referrer и CSP; у приложения нет исходящих API-запросов. Inline style разрешён для прогресс-индикаторов, JavaScript только из собственного origin.

## Обновление

1. Проверить исходники и тесты; сохранить коммит.
2. Создать новый каталог релиза в `/var/www/start90/releases/`, скопировать туда только содержимое dist, сверить SHA-256.
3. Атомарно переключить симлинк current на новый релиз. Изменение файлов не требует reload Caddy.
4. Проверить HTTP→HTTPS, HTTP 200, заголовки и `BASE_URL=https://tgt.myvelum.com npm run test:e2e`.

При изменении конфигурации сначала `caddy validate --config /etc/caddy/Caddyfile`, затем graceful reload, не restart. Перед изменением сделать закрытую резервную копию конфигурации и проверить, что за время операции она не менялась другим процессом. Релиз можно откатить сменой current на предыдущий каталог; browser-local данные пользователей при этом не меняются, совместимость схемы должна сохраняться.

## Ограничения

Публичен только демоинтерфейс. Данные находятся у посетителя в localStorage; нет общей серверной базы, пользовательских учётных записей или конфиденциального канала обращений. Очистка хранилища браузера удалит изменения. Использовать только вымышленные данные.
